# NCEC ROM Tool

**マツダ ロードスター NC（型式 NCEC、LF-VE エンジン、Denso 279700-4073 / Renesas SH7058、CAL ID LFG7EG）**
の純正ECUを、**読み出し・編集・照合・書き込み・ライブ計測**するためのオープンソースツールです。
純正ECUのまま LinkECU / Haltech 風のチューニング環境を目指す、趣味・学習目的のプロジェクトです。

現在のバージョン: **2.81**（`VERSION`。変更履歴は `CHANGELOG_ja.md`）
English: [README.md](README.md)

### 書き込みについて
このECUへの書き込みには、NC1用の **SBL（セカンダリ・ブートローダ）**（書き込み開始 0x2000、0x1800バイト）が必要です。
認証と書き込みシーケンス（`10 85` → `27` → `B1 00 B2 00` → RequestDownload 0x8000/0xFF800 → SBL＋プログラム →
TransferExit → リセット）、チェックサム処理、ブロック長は実装済みで、実機で確認済みです。
**本プロジェクトはSBLを配布しません。** エディタの **［ECU書き込み］** は既定で
`Decryption_sbl/sbl_nc1_flash_0x2000.bin` を読みます。コマンドラインは `tools/flash_writeback.py`
（`--confirm` を付けない限りドライラン）です。

### フラットシフト（ノーリフトシフト）
- 純正のクラッチ連動スロットルカット（`@0x0C53BC`、6500rpm）は、**車速2km/h未満**（`@0x0C53B8`）のときしか効きません。
  停車中の空ぶかし／ローンチ用リミッタとしては働きますが、走行中のフラットシフトには**なりません**。
  （v1.10の説明は誤りで、v1.20で訂正しました。）
- **フラットシフト・パッチ**（`ncecu/flatshift.py`、最終設計）は、**RAMにもレジスタにも一切書き込まない読み取り専用**です。
  固定スクラッチRAMもハードタイマ窓も使いません（v2.50の窓/スクラッチ方式は、実車のMode23可視RAMに安定した空きが無いため廃止）。
  文鎮化の原因になりうる書き込みが無いのが利点です。
- **発動するのは、クラッチ`0xFFFF7100`=1 かつ アクセル>しきい値 かつ 回転>しきい値 かつ 車速>下限 が成立する“間だけ”**。
  窓の長さ＝クラッチを踏んでいる時間（＝ドライバ制御）、回転しきい値が上限として働きます。クラッチを離すと即解除。走行中はスロットルを開けたままにできます。
- **方式を選べます**（CAL `method`）：**0=点火遅角**（最終進角から遅角量を引く＋可変下限`floor`で純正より深い大遅角）/
  **1=点火カット**（コイル充電ハンドラを差し替えて充電をスキップ＝コイル未通電＝火花なし）。
- **`test_mode=1`** は車速ゲートだけ無視（クラッチ＋回転＋アクセルは生かす）＝停車Nでの空ぶかし確認用。
  MT始動のクラッチ踏込は低回転でゲート不成立のため点火を止めません（始動を妨げない）。
- CALは `0xDE300`〜`0xDE318`：`app/rpm/vss/retard/floor`（float）＋`method/test_mode`（u32）。
  既定 APP80% / 回転7000rpm / 車速10km/h / 遅角20° / カット下限−10° / method0 / test_mode0。
- エディタの **［フラットシフト］** ボタン（方式・ゲート・test_modeをダイアログで指定、変更をリザルト表示）、または
  `tools/patch_flatshift_retard.py` で適用します。適用後は、ツリーの **『パッチ - フラットシフト』** で各値を編集できます
  （範囲外の入力は拒否）。停車確認は `tools/flatshift_debug.py`（設定をMode23直読＋ゲートをライブ評価）。
  詳細と実車テスト手順は `docs/tuning_flatshift_ja.md`。
- **実車確認（2026-11-01）**：遅角＝発動中に点火時期（PID 0x0E）が同回転比で約20°低下。
  カット＝点火時期は不変・λ（PID 0x34）がリーン化・バッテリ電圧維持（充電スキップ＝安全）・回転がしきい値付近で頭打ち。両方式とも実機で機能を確認。
- 点火制御を変更するパッチで、排気温度も上がります（特にカット方式）。短時間で、**まずベンチ/予備ECUで確認してください**
  （タイミングライト、またはライブ計測の点火時期 PID 0x0E）。実車ECUには書き込まないこと。

### 回転落ち高速化（レブハング低減）
- シフトアップでアクセルを戻した瞬間（クラッチを切ってエンジンがフリー回転する間）の**回転落ちを速く**します。
  方式は**減速燃料カット（DFCO）を早く・強く効かせる燃料側のみ**で、電子スロットルには一切触れないため、
  E-Gas L2 監視（スロットルがペダル以上に開くのを防ぐ監視）とは原理的に無関係です（＝ブリップ＝回転を上げる側が
  監視で却下されたのと逆の“減らす側”）。
- 主レバー＝**減速突入カウント `0xC477D`（純正30）を下げる**＝リフトから速く燃料カットへ。副レバー＝減速カット率
  `0xCC774`(6×5)/`0xCC694`/`0xCC698`/`0xCC6A0` を上げる＝全カットに速く到達。
  **失速防止の下限 `0xC47FC`(2312.5rpm)・燃料復帰しきい値は不変**（回転落ちを速めても失速側は純正の保護のまま）。
- エディタの **［回転落ち高速化］**（プリセット off/mild/strong・個別値）、または CLI `tools/patch_revdrop.py`。
  既定は inert＝純正等価。`ncecu/antilag.py`（ポップ）とは同番地を逆向きに使うため**1つのROMにはどちらか一方**。
  詳細と段階ベンチ手順は `docs/revdrop_ja.md`。

### アンチラグ（減速時のポップ音）
NA（自然吸気）なので作るのは“音”だけです。排気管内で燃料を燃やすため、触媒・排気系の熱害に注意してください。

| | 名前 | DFCO | 鳴る回転 | 遅角 | ツキ |
|---|---|---|---|---|---|
| **A** | DFCO無効（全回転バーブル） | 無効 | 全回転 | 深い（〜22°） | 純正 |
| **B** | RPMゲート ★おすすめ | **有効** | 有効回転数より上だけ | 20° | 純正 |
| **C** | RPMゲート＋ツキ重視（v2.71 新設） | **有効** | 有効回転数より上だけ | 浅い（12°） | 速い |
| **D** | ツキ重視・DFCO無効（v2.70 までの C） | 無効 | 全回転 | 浅い（12°） | 速い |

- **アンチラグ有効回転数（B・C）**：1500〜6000rpm・100rpm刻み、既定3000。減速燃料カット率の表 `0xCC774` の
  **回転軸 `0xCC748`** を動かしてゲートを置きます。有効回転数以下は無音（通常の燃料カット）、超えると効き始め、
  +1000rpm で完全に有効。既定3000のとき回転軸は純正のまま（v2.70 までの B と同一バイト）。
- ECU 自身の表引きルーチン（`0x20DC`）をエミュレータで実行して確認済み。**実車では未確認**。詳細は統合マニュアルの
  「アンチラグ」章（`docs/tuning_overrun_pops_ja.md`）。

### アイドル回転（目標回転）— マップを直接編集
- v2.71 でアイドル回転補正パッチは廃止しました。ツリーの **Idle Speed - Base** を直接編集します。
- 走行（In-Gear）：制御 `0xD6C9C` / 監視 `0xF4DEC`、非走行（Not In-Gear）：制御 `0xD6CDC` / 監視 `0xF4E2C`。
  検索欄に `0xD6C9C` のように番地を入れると開けます。
- **制御側と監視側（Data Integrity）は必ず同じ値にしてください**（片方だけだと監視不一致でフォルトの原因）。
- 目標が動く“速さ”＝スルーレート（`0xD6AB8`系）は触らないでください（安全監視が保護。実車で P0606 とリンプを確認）。

### 電動ファンの作動水温 — 値は A/D 値（℃ではない）
- **Engine Fan Control** の水温しきい値（中速/高速の作動・停止 `0xBF9F8`〜`0xBF9FE`、アフタークーリングの6表）は、
  水温センサ電圧の 10 ビット A/D 値です（電圧 = 値×5÷1024）。**値が大きいほど低い水温**＝大きくするとファンが早く回ります。
- 表を開くと、説明エリアに ℃ 換算が出ます（いまの値が何℃で入り切りするか・式・目安表）。値を確定すると更新されます。
- 実車純正は 中速 100℃でON / 高速 108℃でON、ベンチECU原本と運用中ROMは 中速 90℃ / 高速 96℃（約10〜12℃早い）。
- 目安：85℃≈143、90℃≈125、95℃≈109、100℃≈96、105℃≈84、110℃≈74。作動値は停止値より小さくします。
- 逆アセンブルで確認した内容です。A/D→℃の換算は実車（2026-11-17、キーON）で ECU 自身の水温と一致しましたが、ファンが回り始める水温そのものはまだ実測していません。詳細は統合マニュアル「チューニングの基本」8.6。

## 動作環境

- Python 3.11 以上（開発は 3.14 / Windows 11）
- CANアダプタ: **gs_usb 系（candleLight。例: DSD TECH SH-C30L）**、500kbps。Zadig で WinUSB ドライバを割り当て
- 依存パッケージ: `pip install -r requirements.txt`
- GUIは Python 標準の tkinter を使用

### ROM定義（マップ定義）
マップ定義には **LibreTuner の `mx5_nc` 定義（作者 speepsio）** を使います。ライセンスを明確にするため
**同梱していません**。以下から入手し、`main.json` と自分のCAL IDの `<CALID>.json`（例: `LFG7EG.json`）を
`defs/libretuner/` に置いてください。
- https://github.com/LibreTuner/LibreTuner（`ui/resources/definitions/mx5_nc/`）

この定義に無い一部の定数（上記フラットシフト関連）は `ncecu/flatshift.py` で定義しており、エディタが追加項目として表示します。

## インストール

```bash
git clone https://github.com/testbenchdev/ncec-rom-tool.git
cd ncec-rom-tool
pip install -r requirements.txt
# LibreTuner の mx5_nc 定義を defs/libretuner/ に置く（上記参照）
python ncec_editor.py
```

## 使い方（概要）

1. **［ROMを開く］** — 吸い出したダンプ（`.bin`、1MB）を読み込む。
2. 左のツリーでマップを選び、セルを編集（数字を打って Enter で確定）。保存時にチェックサムを自動補正。
   **表示**メニューで分割表示（Ctrl+1〜5）・別ウィンドウ・相方（制御⇔監視）の並列表示、**編集**メニュー（または右クリック）で
   補間・平滑化・％変更などの一括操作と元に戻す（Ctrl+Z）。キーは **設定 → ショートカットキー…** で変えられます。
3. **［Live ▶］** — 動作中のECU（OBD-II / CAN）に接続してライブ計測。変化のゆっくりしたPIDは間隔を空けて
   問い合わせ（`ncecu/livelog.py` の `DEFAULT_PID_INTERVALS`）、速いPID（回転数など）の更新を速くします。**［ダッシュボード］** でゲージ表示、
   **［記録 ●］** / **［リプレイ］** でログの記録と再生。
4. **［ECU吸出し］** でECUをダンプ。**［ECUと照合］** / **［ROM照合］** で差分を確認。
5. **［ECU書き込み］** で書き込み（予備/ベンチECU推奨。SBLが必要）。
6. **設定 → パッチ適用** から、**フラットシフト**（点火カット/遅角。読み取り専用設計）、**アンチラグ**（減速ポップ。A〜D、B・Cは有効回転数を指定）、**回転落ち高速化**（DFCO強化・燃料側のみ）、**電スロチューニング**（電子スロットル1:1化）を、開いているROMに適用（いずれも変更したmapをリザルト表示）。アイドル目標回転はマップを直接編集します。
7. 言語ボタンで **日本語 / EN** を切替。**［ヘルプ］** で操作ヘルプを表示し、そこから統合マニュアル（HTML）を開けます。
8. `python tools/build_docs.py` で統合マニュアル（HTML）を、`python tools/gen_manual.py` で全マップのPDFマニュアルを再生成。
