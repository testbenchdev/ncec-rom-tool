# ライブRAM読み出し（KR / クラッチ / 排気温 など）

OBD標準PIDに無い値（ノックカウント・ノック強度・ノックリタード・KR・クラッチスイッチ・排気温など）を、**ECUのMode23（ReadMemoryByAddress）**で既定セッションのままライブ読み出しし、ダッシュボード/ライブパネルに表示する機能。

> ⚠ 本機能の**読み出し側（ダッシュボード）**は本ツールが提供します。一方、それを可能にする
> **「Mode23有効化パッチ」はユーザ自身がROMへ適用**してください（Mode23の認証を外す改変＝
> セキュリティ低下に当たるため、本ツールではパッチ生成・書き込みを行いません）。予備/ベンチECUで、
> 吸い出しバックアップの上で。⚠ 有効化すると**認証なしでRAM/ROMを読める**状態になります（書込は別サービスで不可）。

## 1. なぜMode23か（調査結果）

- このECUは標準OBD(Mode01)しか配信せず、Mode22も番号体系がMode01と共通で、**KR/クラッチ/排気温は標準では読めません**。
- 一方、ECUの**Mode23読み出しハンドラ(`0x7F874`)はRAM `0xFFFF0000`〜`0xFFFFE000` を既に許可**しています（ROM `0`〜`0x100000` と並んで。サイズ 1〜0x400）。
- よって**Mode23を既定セッションで通せば**、`23 <addr:4 BE> <size:2 BE>` → `63 <data>` で**任意のRAMをライブ読み出し**できます。

## 2. Mode23有効化パッチ（ユーザが適用）

既定セッションのまま Mode23 を通すには、**2つの関所**を両方開ける必要があります。合計**3バイト**の変更＋**チェックサム再計算**です（番地は逆アセンブルで確定済み。ベンチ `ncec_rom_dump.bin`／実車 `ecu_readout_original.bin`／運用中 `ncec_immo_off.bin` の3ROMで該当バイト一致を確認＝同じオフセットで当たる）。

| 番地 | 純正 | 有効化後 | 意味 |
|---|---|---|---|
| `@0x84C04` | `0x00` | `0x10` | flags上位。flags dword = `0x1000000F`（Mode22と同じ＝既定セッション可） |
| `@0x84C07` | `0x06` | `0x0F` | flags下位 |
| `@0x7F734` | `0x8F17` | `0x0009` | ハンドラ内の認証NG分岐(bf/s→NRC33)をnop化 |

### 2.1 なぜ3バイトか（2つの関所）

**関所①：ディスパッチャの flags（→ `0x84C04` / `0x84C07`）**
診断ディスパッチ表 `@0x84BFC` の SID 0x23 エントリは `handler=0x0007F708` / `flags=0x00000006`。flags dword は **`@0x84C04`** にあり、`0x00000006` は「要プログラミングセッション」。既定セッションではハンドラに届く前にディスパッチャが **NRC 0x22**（conditionsNotCorrect）で弾きます。先頭バイト `@0x84C04`(0x00→0x10) と末尾バイト `@0x84C07`(0x06→0x0F) を変えて **`0x1000000F`**（＝Mode22と同じ「既定セッション可」）にします。中間の `0x84C05/06` は `0x00` のまま。

**関所②：ハンドラ内の認証チェック（→ `0x7F734`）**
ハンドラ `0x7F708` 内、認証判定の直後：

```
07F72C  jsr  @r2           ; 認証ヘルパ(0x7DDF4) 呼び出し
07F730  extu.b r0,r0
07F732  tst  r0,r0         ; T = (r0==0 = 認証OK)
07F734  bf/s 0x7F766       ; 認証NG(r0!=0) なら NRC 経路へ分岐  ← ここをnop化
07F736  nop
07F738  ...                ; 以降=読み出し経路(0x7F874 を呼ぶ)
```

`@0x7F734` の `bf/s`（`0x8F17`）を **nop（`0x0009`）** にすると、認証結果に関わらず読み出し経路へ進みます（これが無いとディスパッチを通っても **NRC 0x33** を返す）。

### 2.2 適用手順（ユーザ自身で）

1. **吸い出しバックアップを保管**（予備/ベンチECU推奨）。
2. 上表の**3バイトを書き換え**。
3. **チェックサムを再計算**（領域 `@0xFF650`〜`0xFF7FC`、magic `0x5AA5A55A`）。本ツールの `ncecu.checksum.recalculate(data)` がこの計算です。**再計算を忘れるとECUが整合不良で受け付けません。**
4. そのROMをECUへ書き込み。
5. **書き込み後は確実に電源を再投入**（GNDだけでなく**+12V側も切る**。GNDだけだとMCU/RAMが生き残り、プログラミング直後の状態が残って Mode23 が通らないことがある＝既知の落とし穴）。

### 2.3 確認・注意

- 適用済みか判定：`ncecu.mode23.is_enabled_rom(data)` が3点の有無を見ます（参考番地・範囲判定も `ncecu/mode23.py` に資料として記載）。
- 戻すとき：3バイトを純正値へ戻し、再度チェックサム再計算。
- ⚠ 有効化すると**認証なしでRAM/ROMを読める**状態になります（書き込みは別経路なので不可）。個人利用前提で。
- 本ツールは**この3点の生成・書き込み（パッチ生成器）は提供しません**（認証を外す改変＝セキュリティ低下に当たるため）。上記は、**ユーザ自身が手元の手段で適用する**ための手順解説です。

## 3. 読み出し側（ダッシュボード）の使い方

Mode23有効化ROMを書いたECUに `[Live ▶]` で接続すると、自動で下記RAMを読み、ライブパネルに「RAM …」行で表示します。ダッシュボードにもタイルとして追加できます（右クリック→追加に「クラッチ/KR/排気温」が出ます）。

| 表示 | 既定の番地 | 型 | 状況 |
|---|---|---|---|
| クラッチ | `0xFFFF6FCC` | u8（0/1） | **確定** |
| 排気温（触媒推定） | `0xFFFF777C` | float °C | **確定**（PID 0x3C が読む値。実排気温センサは無いので推定） |
| KR（ノック遅角） | `0xFFFF7C4C` | float ° | **候補**。実車でノックを出して追従するか確認し、違えば下記で変更 |
| ノックカウント | `0xFFFF7C3A` | u8 | **確度高**（Proto-Knock Count。下記5章） |
| ノック強度 | `0xFFFF7C60` | float | **候補**（Proto-Knock Magnitude ピーク） |
| ノックリタード（適用） | `0xFFFF7C44` | float ° | **候補**（適用中のノックリタード蓄積） |

- **未有効化のECU**に接続した場合は、数回のNRCで自動的にRAM読み出しを停止し、ライブパネルに「Mode23未有効化のため読めません」と表示します（通常のPID計測は続行）。
- ノックの暫定確認は、パッチ無しでも**PID 0x0E（点火時期）の落ち込み**で傾向は見えます。

## 3.5 ノック（Proto-Knock）の値について

純正のノック制御（Denso「**Proto-Knock**」方式）を逆アセンブルして特定した値です。ノック用RAMブロックは **`0xFFFF7C20`〜`0xFFFF7CD0`**。ベンチROMと実車ROM（同CAL `LFG7EG`）で該当コードは**完全一致**＝実車にそのまま転用できます。

| 値 | 番地 | 意味 | 確度 |
|---|---|---|---|
| ノックカウント | `0xFFFF7C3A` | プロトノック検出カウント（0〜255飽和）。cal「Minimum Proto-Knock Count for Successful Knock Event」(=24) と比較して成立判定 | **高**（cal と直結を確認） |
| （成立フラグ） | `0xFFFF7C3C` | カウント≥24 で「ノック成立」1。※既定タイル未登録。必要なら `ram_reads.json` で追加可 | **高** |
| ノック強度 | `0xFFFF7C60` / `0xFFFF7C6C` | Proto-Knock Magnitude のピーク（`fmax` 保持）。ノック信号の強さ | **中** |
| ノックリタード | `0xFFFF7C44` | 適用中のノックリタード蓄積 | **中** |
| （気筒別背景） | `0xFFFF7C78`〜`7B` | 気筒別の適応バックグラウンド（ノイズ基準、初期 `0x80`） | **中** |

- **見どころ**：点火を進めてノックが出ると、**カウント `0xFFFF7C3A` が跳ね上がり**（24で「成立」）→ **リタード `0xFFFF7C44`** が入ります。**強度 `0xFFFF7C60`** はノック信号の大きさです。
- ダッシュボードの既定レンジ・アラーム：カウントは成立しきい値 **24** で赤、リタードは **5°** で赤。**強度の数値レンジはECU内部スケール依存**なので、実車の値を見て右クリック→「スケール」で調整してください。
- 生の高周波波形そのものはサンプリング割り込み内にしか無く、スカラ値としては取得できません。チューニングで使う「ノックセンサ値」はこの Proto-Knock（カウント／強度）です。
- 気筒別の強度4本の個別割り当ては実車で確認が確実です（まずはカウント＋強度ピークで十分見えます）。

## 4. 設定の変更（`ram_reads.json`）

既定は `ncecu/livelog.py` の `RAM_CHANNELS`。変更したいときはプロジェクト直下に `ram_reads.json` を置きます（`.gitignore` 済み）。例:

```json
[
 {"ch": 257, "addr": 4294930380, "type": "u8",  "role": "CLUTCH",   "name": "クラッチ",       "unit": "",   "interval": 0.2},
 {"ch": 258, "addr": 4294933580, "type": "f32", "role": "KR",       "name": "KR(ノック遅角)", "unit": "°",  "interval": 0.5},
 {"ch": 259, "addr": 4294932860, "type": "f32", "role": "EGT",      "name": "排気温",          "unit": "°C", "interval": 2.0},
 {"ch": 260, "addr": 4294933562, "type": "u8",  "role": "KNOCKCNT", "name": "ノックカウント",  "unit": "",   "interval": 0.2},
 {"ch": 261, "addr": 4294933600, "type": "f32", "role": "KNOCKMAG", "name": "ノック強度",      "unit": "",   "interval": 0.2},
 {"ch": 262, "addr": 4294933572, "type": "f32", "role": "KNOCKRTD", "name": "ノックリタード",  "unit": "°",  "interval": 0.5}
]
```

- `ch` は合成キー（`0x100`台＝257〜。実PIDと衝突しない）。`addr` は10進でも可（例 `0xFFFF6FCC` = 4294930380）。
- `type`：`u8`/`u16`/`s16`/`u32`/`s32`/`f32`（いずれもビッグエンディアン）。`scale`/`offset` 省略可（`値=生×scale+offset`）。
- `interval`：読み出し間隔[秒]。クラッチは速め、排気温は遅めが目安。**GUIからも**「設定 → ライブPID間引き…」ダイアログ下部の「ライブRAM」欄で変更できます（保存先は同じ `ram_reads.json`）。
- **KRの番地が違っていたら** ここで `addr` を直してください。範囲は `0xFFFF0000`〜`0xFFFFE000` 内（サイズ合計がこの範囲）。

## 5. 注意

- 読み出しは**既定セッション・読み取り専用**（`10 85` などのセッション変更はしない）。走行中もエンジン動作に影響しません。
- Mode23有効化は**認証を外す**ため、バス上の誰でもRAM/ROMを読めます。個人利用前提で。戻すときは3点を純正値に戻してチェックサム再計算。
- KRは候補番地です。実車で確認してから運用してください。
