# ライブRAM読み出し（クラッチ / 減速ステータス / KR / 排気温 / ノック / 噴射パルス幅 など）

OBD標準PIDに無い値（クラッチ・減速ステータス・ノックカウント・ノック強度・ノックリタード・KR・排気温など）を、**ECUのMode23（ReadMemoryByAddress）**で既定セッションのままライブ読み出しし、ダッシュボード/ライブパネルに表示する機能。

> ⚠ 本機能の**読み出し側（ダッシュボード）**は本ツールが提供します。一方、それを可能にする
> **「Mode23有効化パッチ」はユーザ自身がROMへ適用**してください（Mode23の認証を外す改変＝
> セキュリティ低下に当たるため、本ツールではパッチ生成・書き込みを行いません）。予備/ベンチECUで、
> 吸い出しバックアップの上で。⚠ 有効化すると**認証なしでRAM/ROMを読める**状態になります（書込は別サービスで不可）。

## 1. なぜMode23か（調査結果）

- このECUは標準OBD(Mode01)しか配信せず、Mode22も番号体系がMode01と共通で、**KR/減速ステータス/排気温は標準では読めません**。
- 一方、ECUの**Mode23読み出しハンドラ(`0x7F874`)はRAM `0xFFFF0000`〜`0xFFFFE000` を既に許可**しています（ROM `0`〜`0x100000` と並んで。サイズ 1〜0x400）。
- よって**Mode23を既定セッションで通せば**、`23 <addr:4 BE> <size:2 BE>` → `63 <data>` で**任意のRAMをライブ読み出し**できます。

## 2. Mode23有効化パッチ（ユーザが適用）

既定セッションのまま Mode23 を通すには、**2つの関所**を両方開ける必要があります。合計**3バイト**の変更＋**チェックサム再計算**です（番地は逆アセンブルで確定済み。ベンチ純正・実車純正・当時の運用ROMの3本で該当バイト一致を確認＝同じオフセットで当たる）。

| 番地 | 純正 | 有効化後 | 意味 |
|---|---|---|---|
| `@0x84C04` | `0x00` | `0x10` | flags上位。flags dword = `0x1000000F`（Mode22と同じ＝既定セッション可） |
| `@0x84C07` | `0x06` | `0x0F` | flags下位 |
| `@0x7F734` | `0x8F17` | `0x0009` | ハンドラ内の認証NG分岐(bf/s→NRC33)をnop化 |

### 2.1 なぜ3バイトか（2つの関所）

**関所①：ディスパッチャの flags（→ `0x84C04` / `0x84C07`）**
診断ディスパッチ表 `@0x84BFC` の SID 0x23 エントリは `handler=0x0007F708` / `flags=0x00000006`。flags dword は **`@0x84C04`** にあり、`0x00000006` は「要プログラミングセッション」。既定セッションではハンドラに届く前にディスパッチャが **NRC 0x22**（conditionsNotCorrect）で弾きます。先頭バイト `@0x84C04`(0x00→0x10) と末尾バイト `@0x84C07`(0x06→0x0F) を変えて **`0x1000000F`**（＝Mode22と同じ「既定セッション可」）にします。中間の `0x84C05/06` は `0x00` のまま。

**関所②：ハンドラ内の認証チェック（→ `0x7F734`）**
ハンドラ `0x7F708` 内、認証判定の直後：

```
07F72C  jsr  @r2           ; 認証ヘルパ(0x7DDF4) 呼び出し
07F730  extu.b r0,r0
07F732  tst  r0,r0         ; T = (r0==0 = 認証OK)
07F734  bf/s 0x7F766       ; 認証NG(r0!=0) なら NRC 経路へ分岐  ← ここをnop化
07F736  nop
07F738  ...                ; 以降=読み出し経路(0x7F874 を呼ぶ)
```

`@0x7F734` の `bf/s`（`0x8F17`）を **nop（`0x0009`）** にすると、認証結果に関わらず読み出し経路へ進みます（これが無いとディスパッチを通っても **NRC 0x33** を返す）。

### 2.2 適用手順（ユーザ自身で）

1. **吸い出しバックアップを保管**（予備/ベンチECU推奨）。
2. 上表の**3バイトを書き換え**。
3. **チェックサムを再計算**（領域 `@0xFF650`〜`0xFF7FC`、magic `0x5AA5A55A`）。本ツールの `ncecu.checksum.recalculate(data)` がこの計算です。**再計算を忘れるとECUが整合不良で受け付けません。**
4. そのROMをECUへ書き込み。
5. **書き込み後は確実に電源を再投入**（GNDだけでなく**+12V側も切る**。GNDだけだとMCU/RAMが生き残り、プログラミング直後の状態が残って Mode23 が通らないことがある＝既知の落とし穴）。

### 2.3 確認・注意

- 適用済みか判定：`ncecu.mode23.is_enabled_rom(data)` が3点の有無を見ます（参考番地・範囲判定も `ncecu/mode23.py` に資料として記載）。
- 戻すとき：3バイトを純正値へ戻し、再度チェックサム再計算。
- ⚠ 有効化すると**認証なしでRAM/ROMを読める**状態になります（書き込みは別経路なので不可）。個人利用前提で。
- 本ツールは**この3点の生成・書き込み（パッチ生成器）は提供しません**（認証を外す改変＝セキュリティ低下に当たるため）。上記は、**ユーザ自身が手元の手段で適用する**ための手順解説です。

## 3. 読み出し側（ダッシュボード）の使い方

Mode23有効化ROMを書いたECUに `[Live ▶]` で接続すると、自動で下記RAMを読み、ライブパネルに「RAM …」行で表示します。ダッシュボードにもタイルとして追加できます（右クリック→追加に「クラッチ/減速ステータス/KR(ノック遅角)/排気温」が出ます）。

| 表示 | 既定の番地 | 型 | 状況 |
|---|---|---|---|
| クラッチ | `0xFFFF7100` | u8（0/1） | **実車で特定**。0=離す／1=踏む。ROM参照14箇所の本家クラッチスイッチ（下記） |
| 減速ステータス（旧称クラッチ） | `0xFFFF6FCC` | u8（0/1） | **実車確認済み**。0=駆動中（ギア入・アクセルON）／1=減速コースト・ニュートラル・アイドル・停止。**クラッチ入力ではない**（下記） |
| 排気温（触媒推定） | `0xFFFF777C` | float °C | **確定**（PID 0x3C が読む値。実排気温センサは無いので推定） |
| **ノックレベル** | `0xFFFF4E20` | float | **確定**（ノックセンサの強さ。しきい値 `0xFFFF4E58` を超えると検出。連続値＝余裕度が見える。内部スケール） |
| **KR（ノック遅角）** | `0xFFFF7C44` | float ° | **確定**（2026-11-14。0=遅角なし、>0で作動。+1.7°→0.17°ずつ減衰をログで確認。3.5章） |
| ゲートAPP | `0xFFFF56C8` | float %（0〜100） | **確定**（フラットシフトのゲートが読むアクセル開度。OBDペダルPID 0x49とは別物。80%ゲートの実走WOT校正用） |
| 噴射パルス幅（IPW） | `0xFFFF7380` | float ms | **確定**（実走ログで特定。インジェクタの実噴射時間。減速燃料カットで0msに落ちる。下記） |
| 開弁率（duty） | 派生（RAMではない） | float %（0〜100） | **派生値**＝`IPW×RPM/1200`。`livelog`が計算してダッシュボード/ログへ（ch `0x10A`） |

> **ノック監視は「レベル＋KR」の2本に集約**（ユーザー指示）。レベルで信号の強さ、KRで遅角が入ったかが分かる。
> 下記は既定の表示から外した（見たいときは `ram_reads.json` で追加）：
> - ノックイベント `0xFFFF7C3C`（u8 0/1）・生検出 `0xFFFF7E89`（u8 0/1）＝KRが立つ元の判定。KRがあれば冗長。
> - しきい値 `0xFFFF4E58`（float）＝レベルと対で記録すると余裕度（しきい値までの差）が出る。
> - 始動後燃焼カウント `0xFFFF7C3A`（旧称ノックカウント）＝始動直後すぐ255飽和。ノック回数ではない。
> - `0xFFFF7C60`（旧称ノック強度）＝未確認／`0xFFFF7C4C`（旧称KR）＝KR積算の最小KRの引き値でKRではない。

- **未有効化のECU**に接続した場合は、数回のNRCで自動的にRAM読み出しを停止し、ライブパネルに「Mode23未有効化のため読めません」と表示します（通常のPID計測は続行）。
- ノックの暫定確認は、パッチ無しでも**PID 0x0E（点火時期）の落ち込み**で傾向は見えます。

### 減速ステータス(0xFFFF6FCC)と本物のクラッチ(0xFFFF7100) — 実車で特定

実車ログ／RAM差分で確認した結果：
- **`0xFFFF6FCC` = 減速ステータス**（旧称「クラッチ」は誤り）。0=駆動中（ギア入・アクセルON）／1=減速コースト・ニュートラル・アイドル・停止。定義の「Decel Transition … Hold Decel Status | In-Gear」に対応。
- **`0xFFFF7100` = 本物のクラッチスイッチ**（0=離す／1=踏む）。ROM参照14箇所の本家入力で、燃料カット・回転リミッタ等が参照。

**特定方法**（`tools/ram_diff.py`）：Mode23でRAM全域を**クラッチON/OFFで複数回読み比べ、毎回連動するバイトの共通集合**をとる。KOEO（イグニッションON・エンジンOFF）で数サイクル回すと 757→174→68→13→収束。13個のうち**クリーンな0↔1かつ参照最多の `0xFFFF7100`** が本家（他は派生・反転・押下カウンタ）。定義の「P0704 – CPP switch input circuit problem」＝クラッチ回路DTCの存在とも整合。

→ フラットシフトのトリガは `0xFFFF7100`（本物のクラッチ）に**作り直し済み**（`ncecu/flatshift.py` / `docs/tuning_flatshift_ja.md`）。

### 噴射パルス幅(0xFFFF7380)と開弁率 — 実走ログで確定

OBDにインジェクタ開弁時間のPIDは無いため、Mode23でRAMから読む。静的RE＋**2026-11-02の実走ログ（6408rec/193s、アイドル＋負荷プル＋惰行）**で `0xFFFF7380` を**実噴射パルス幅（IPW, ms）**と確定した。

- **決め手＝惰行燃料カットで 0.000ms に落ちる**（＝インジェクタ停止）。負荷/MAP/MAFと強い正相関（r≒0.97）、RPMとは弱（0.19）＝空気量で決まる噴射らしい挙動。アイドル約2ms／全開約11msで物理的に妥当。
- 燃料計算の連鎖は **`0xFFFF7374`（カット前の要求ベース）→ ×補正[`0xFFFF7550`/100] → `0xFFFF7380`（最終・実噴射）**。`0xFFFF7374` はカット中も0に落ちず（最小約0.85ms）＝要求値なので**不採用**。`0xFFFF7378`/`0xFFFF737C` は `0xFFFF7380` のパイプライン中間値（定常で同値、過渡で1サイクルずれる）。
- 旧候補 `0xFFFF7498` は実車ログで否定済み（0.47〜0.62でほぼ一定・負荷と負相関＝デッドタイム相当）。
- **開弁率[%]** は `IPW[ms]×RPM/1200`（4ストローク＝2回転に1噴射）の派生値で、`ncecu/livelog.py` が毎周期計算してログ・ダッシュボードへ流す（ch `0x10A`、RAM読み出しではない）。ダッシュボードには右クリック→「項目を追加」→「噴射パルス幅」「開弁率」で出せる。
- 備考：`0xFFFF6FCC`（減速ステータス）は**燃料カットフラグではない**（実カット中はむしろ0だった）。カット判定はIPWが0msに落ちることで直接見える。

## 3.5 ノック（Proto-Knock）の値について

純正のノック制御を逆アセンブルし、**全ログと突き合わせて確定**した値です（2026-11-14。経緯と根拠は `docs/knock_re_ja.md`）。この章の旧記述（「カウントが跳ね上がる」「強度 `0xFFFF7C60`」など）は誤りだったので差し替えました。ベンチROMと実車ROM（同CAL `LFG7EG`）で該当コードは**完全一致**です。

| 値 | 番地 | 意味 | 確度 |
|---|---|---|---|
| **KR（ノック遅角）** | `0xFFFF7C44`（本体 `0xFFFF7C20`） | ノックで **+1.7°**（上限8°）、その後 **0.17°/燃焼**（負荷40%未満では 0.3515°/燃焼）で戻る | **確定**（ログの実測が cal と一致） |
| ノックイベント | `0xFFFF7C3C` | 生検出 かつ 始動後24燃焼以上で 1（1燃焼ぶんだけ立つ） | **確定** |
| ノック生検出 | `0xFFFF7E89`（元 `0xFFFF4E14`） | 今回のノックレベル ≥ 適応しきい値 で 1 | **確定** |
| **ノックレベル** | `0xFFFF4E20` | 気筒イベントごとのセンサの強さ（float）。しきい値を超えると生検出。**既定で監視**（ch 0x114） | **確定** |
| しきい値 | `0xFFFF4E58` | その時点の適応しきい値（float）。レベルと対で記録すると余裕度が出る。既定では読まない | **確定**（任意で追加） |
| 始動後燃焼カウント | `0xFFFF7C3A` | 始動から数えた燃焼回数。**255で飽和**＝走行中は常に255 | **確定**（ノック回数ではない。既定で読まない） |

- **監視はレベルとKRの2本**（ユーザー指示）。**レベル `0xFFFF4E20`** でセンサの強さ、**KR `0xFFFF7C44`** で遅角が実際に入ったかが分かります。ノックセンサは0/1ではなくアナログで、0/1の検出フラグはレベルがしきい値を超えたかの結果にすぎません。
- **見どころ**：ノックが出ると **KR が 1.7° に跳ね、約0.25秒で0に戻ります**。同時に点火時期（PID 0x0E）が1〜2°落ちます。短いので読み出し間隔は 0.2秒以下にしてください。
- ダッシュボードの既定アラーム：**KR が 1.5° 以上で赤**（＝ノック遅角が1回入った）。旧設定の「カウント24で赤」は走行中ずっと赤になる誤りだったので撤去しました。
- **レベルの数値レンジはECU内部スケール**です。実車の値を見て右クリック→「スケール」で調整してください（既定は仮に0〜5）。しきい値までの余裕を見たいときは `ram_reads.json` にしきい値 `0xFFFF4E58`（f32）も足します。

## 4. 設定の変更（`ram_reads.json`）

既定は `ncecu/livelog.py` の `RAM_CHANNELS`。変更したいときはプロジェクト直下に `ram_reads.json` を置きます（`.gitignore` 済み）。例:

```json
[
 {"ch": 257, "addr": 4294930380, "type": "u8",  "role": "DECEL",    "name": "減速ステータス",  "unit": "",   "interval": 0.2},
 {"ch": 259, "addr": 4294932348, "type": "f32", "role": "EGT",      "name": "排気温",          "unit": "°C", "interval": 2.0},
 {"ch": 276, "addr": 4294921760, "type": "f32", "role": "KNOCKLVL", "name": "ノックレベル",    "unit": "",   "interval": 0.2},
 {"ch": 262, "addr": 4294933572, "type": "f32", "role": "KR",       "name": "KR(ノック遅角)", "unit": "°",  "interval": 0.2},
 {"ch": 265, "addr": 4294931328, "type": "f32", "role": "IPW",      "name": "噴射パルス幅",    "unit": "ms", "interval": 0.1}
]
```

- `ch` は合成キー（`0x100`台＝257〜。実PIDと衝突しない）。`addr` は10進でも可（例 `0xFFFF6FCC` = 4294930380）。
- `type`：`u8`/`u16`/`s16`/`u32`/`s32`/`f32`（いずれもビッグエンディアン）。`scale`/`offset` 省略可（`値=生×scale+offset`）。
- `interval`：読み出し間隔[秒]。減速ステータスは速め、排気温は遅めが目安。**GUIからも**「設定 → ライブPID間引き…」ダイアログ下部の「ライブRAM」欄で変更できます（保存先は同じ `ram_reads.json`）。
  選択肢は PID と共通で **毎回(0) / 0.1 / 0.2 / 0.5 / 1 / 2 / 5 / 10 秒 / 無視(-1)**。**無視**にした項目は読みません。
- **ブレーキ2(冗長) `0xFFFF70EE` は既定で「無視」**（ブレーキ `0xFFFF70EC` と同じ踏み込みの重複。必要なら間引き設定で戻せます）。
- 番地を変えるときは `addr` を直します。範囲は `0xFFFF0000`〜`0xFFFFE000` 内（サイズ合計がこの範囲）。

### ライブRAMの読み方と更新速度（v2.71）

- ライブRAMは **隣り合う番地しか1回でまとめて読めません**（1ブロック＝1往復）。離れた番地の項目を増やすほど、
  1周期の往復が増えて全体の更新（回転・負荷＝MAP追従）が遅くなります。
- そこで **1周期に読むRAMは2ブロックまで**とし、設定間隔からの**遅れが大きい順**に読みます。回転・負荷などPID側の
  周期は一定に保たれ、RAM側は「設定間隔を目標にしたベストエフォート」になります（読み切れない分は次の周期へ）。
- 目安（机上シミュレーション。1往復の所要時間は仮定値、**実機未計測**）：毎回読むRAMが2本＋0.1〜0.2秒のRAMが4本の設定で、
  全体の周期が約1.5倍速くなる代わりに、RAM各項目の更新は設定の6〜8割程度になります。
- 速くしたいときは、使わない項目を **無視** にするのが一番効きます。

## 5. 注意

- 読み出しは**既定セッション・読み取り専用**（`10 85` などのセッション変更はしない）。走行中もエンジン動作に影響しません。
- Mode23有効化は**認証を外す**ため、バス上の誰でもRAM/ROMを読めます。個人利用前提で。戻すときは3点を純正値に戻してチェックサム再計算。
- KR（`0xFFFF7C44`）は実車ログで確定済みです（3.5章）。ノックレベルの数値レンジは内部スケールなので、実車で見て調整してください。
