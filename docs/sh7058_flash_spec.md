# 無印 SH7058 フラッシュ・プログラミング仕様(SBL自作用まとめ)

出典: **SH-2E SH7058 F-ZTAT Hardware Manual, Rev.3.00 (2004.09)** 第23章(ルネサス公式)
→ docs/sh7058_plain_manual.pdf
方式: **ダウンロード方式**(チップ内蔵のプログラミング/消去ルーチンをRAMへ展開して呼ぶ)。
手順プログラム(=SBL)はユーザーが書く。SH7058S/7059と同一方式・同一レジスタ(0xFFFFE800〜)。

## フラッシュ制御レジスタ(8bit, バイトアクセス)

| レジスタ | アドレス | 役割 |
|---|---|---|
| FCCS  | 0xFFFFE800 | SCOビットで内蔵プログラムのダウンロード起動 |
| FPCS  | 0xFFFFE801 | bit0 PPVS=1 で「書き込みプログラム」を選択 |
| FECS  | 0xFFFFE802 | bit0 EPVB=1 で「消去プログラム」を選択 |
| FKEY  | 0xFFFFE804 | H'A5 書き込みで SCO 有効化、H'5A で書込/消去実行許可 |
| FMATS | 0xFFFFE805 | ユーザMAT/ユーザブートMAT 選択 |
| FTDAR | 0xFFFFE806 | ダウンロード先RAMアドレス(先頭1バイト有効) |

※ FWE 端子 High かつ ユーザプログラムモードが必要。動作周波数は書込/消去時 最大40MHz。

## 手順(SBL がやること)

### 1. ダウンロード
1. VBR = 0x00000000 にクリア
2. FPCS.PPVS=1(書込)または FECS.EPVB=1(消去)で、落とすプログラムを選択
3. FTDAR = ダウンロード先RAMアドレス指定
4. ダウンロード先RAM先頭バイト(DPFR)を H'FF 以外の既知値に初期化(誤判定防止)
5. FKEY = H'A5
6. FCCS.SCO = 1 → 自動ダウンロード(ユーザMATが内蔵プログラム領域に置換される)
7. **DPFR(ダウンロード先RAM先頭1バイト)で結果確認**: ダウンロード前と異なる値になり、
   SS(bit2)/FK(bit1)が0なら成功。
8. ダウンロード後 VBR は戻してよい。

### 2. 初期化(ダウンロードした init ルーチンをJSR)
- エントリ: **FTDAR指定アドレス + 16**
- 引数: R4 = FPEFEQ(動作周波数, MHz 値), R5 = FUBRA(ユーザ分岐先アドレス; 不要なら所定値)
- 戻り: R0 = FPFR(0=正常)

### 3. 書き込み(128バイト単位)
- 事前に対象ブロックを消去しておくこと。
- FKEY = H'5A(実行許可)
- 引数: R5 = FMPAR(書き込み先フラッシュアドレス), R4 = FMPDR(128バイトのデータ元RAMアドレス)
- エントリ: **FTDAR指定アドレス + 32**(処理エントリ)を JSR
- 戻り: R0 = FPFR(0=正常)
- 連続書込時はアドレス/データを更新して再JSR(再ダウンロード不要)。

### 4. 消去(1ブロック単位)
- FECS で消去プログラムをダウンロードしておく(2と同様に別途ダウンロード)。
- FKEY = H'5A
- 引数: R4 = FEBS(消去ブロック番号 EB0〜EB15)
- エントリ: FTDAR指定アドレス + 32 を JSR
- 戻り: R0 = FPFR(0=正常)

## フラッシュのブロック構成(消去単位, docs/SH7058_hardware_notes.md より)
- EB0–EB7: 4KB×8 (0x00000–0x07FFF)
- EB8: 96KB (0x08000–0x1FFFF)  ※ 実際の構成はマニュアル第23章の図で要再確認
- EB9–EB15: 128KB×7 (0x20000–0xFFFFF)

## SBL 実装で残っている確認事項
- FTDAR の値→RAMアドレスの対応(先頭1バイト=上位アドレス)。ダウンロードサイズ(約2〜3KB)。
- FPEFEQ の周波数エンコード(実機の動作周波数。PLL逓倍後 φ)。
- init/process の正確なエントリオフセット(+16/+32 を本文の図で最終確認)。
- 書込/消去それぞれで別ダウンロードが要るか、FPCS/FECS切替で足りるか。

## ECU↔SBL ハンドオフ(RTOSの壁 — 静的解析では未解決)
ECU は 0x34/0x36 でSBLをRAM 0x8000へ受領 → RTOSフラッシュタスクがSBLを実行しデータを渡す。
受け渡しABIはRTOSタスク内。追跡結果:
- 0x34(0x7F610)/0x36(0x7F688) → 検証後 0x79F8A → [0x7a038]=**0x8E4FA** → [0x8e534](RTOSメッセージ送信プリミティブ)。
- 即値 0x8000 への jmp/jsr は ROM 内に無い(ハンドオフはダウンロード先変数経由でタスク内)。
- = CVN と同じ「RTOSタスクの静的解析」壁。これ以上の静的RE突破は非現実的。

## ★ 現実的な突破口(SBLの入手)
SBL は**フラッシュ中に 0x36 TransferData で平文送信される**。したがって:
- **実機を1回フラッシュした際の CAN バスキャプチャ**(nc-flash/RomDrop + Tactrix を使った誰かのログ、
  または 0x36 ペイロードのダンプ)があれば、その最初の転送ブロック群 = **SBLバイナリそのもの**。
- それを `ncecu/flash.py` に sbl_data として渡せば、完成済みホスト側ドライバでそのまま書き込める。
- 代替: nc-flash の非公開 _secure(get_sbl_data)。
ハンドオフABIを解く必要すらなく、SBLブロブを一度入手すれば書き込みが可能になる(ドライバは検証済み)。
