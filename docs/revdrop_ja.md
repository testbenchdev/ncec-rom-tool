# シフトアップ時の回転落ち高速化（レブハング低減）— RE と編集方法

アクセルを戻した瞬間（クラッチを切ってエンジンがフリー回転する間）の**回転落ちを速くする**ための、
純正ECU向け ROM 編集。**燃料側のみ（減速燃料カット=DFCO を早く・強く）**で電子スロットルには
いっさい触らないため、E-Gas L2 監視とは原理的に無関係＝弾かれる筋が無い。

- 本体ロジック・番地：`ncecu/revdrop.py`
- CLI：`tools/patch_revdrop.py`
- エディタ：設定→パッチ→「回転落ち高速化（レブハング低減）」
- 段階ベンチ手順：この文書の末尾「段階ベンチ手順」
- 対象 CALID：LFG7EG（ベンチ純正・実車純正・運用中ROMの3本で番地一致・確認済み）

> ⚠ 予備/ベンチECU専用。実車の純正PCMには書かない。実機フラッシュはユーザー明示確認のうえ別途。

---

## 1. なぜ「燃料を減らす向き」なら安全なのか

E-Gas L2（第2階層の独立監視）は「**スロットルがペダルの要求以上に開く**」危険側を検出してトリップする
のが役目。オートブリップ（＝回転を上げる＝空気/スロットルを**増やす**向き）が段階B/C-FF/D で L2 に
却下された（`docs/project_index_ja.md` §13）のは、まさにこの「増やす側」だったから。

回転落ちを速くする本件は**燃料を減らす（早くカットする）向き**で、スロットル開度は一切変えない。
監視が守る軸（スロットル vs ペダル）に触れないので、この路線は実現可能性が高い——という読みどおり、
RE でも「編集するのは燃料カットの突入タイミングとリーン化レートだけ」で済むことを確認した。

## 2. 回転落ちの仕組みと効くレバー

シフトアップは「アクセル戻し→クラッチ切り→（エンジンがフリー回転）→次ギアでクラッチ接」。この
**フリー回転の間**に回転が速く落ちてほしい。クラッチが切れているのでミッション側のエンジンブレーキは
効かず、回転落ちは「燃焼トルク（正）− フリクション − ポンピング損失」で決まる。

- **燃料が残っていると燃焼で正トルクが出て回転が落ちない＝レブハング**。→ **DFCO で燃料を早く切れば**
  燃焼トルクが消え、フリクション＋ポンピングで回転が速く落ちる。これが本件の主レバー（燃料側・監視安全）。
- スロットルは閉ペダルで純正でも既に全閉指令（§4）なので、定常の「開きっぱなし」は無い。残る寄与は
  過渡の閉じレート（ダッシュポット）だが、これはコード側で監視保護の懸念があり本件では扱わない（§5）。

## 3. 変更する番地（燃料側・監視安全）

| 役割 | 番地 | 型/寸法 | 純正値 | 変更の向き |
|---|---|---|---|---|
| **減速突入カウント**（減速状態に入るのに必要なデバウンス回数） | `0xC477D` | uint8 | 30 | **下げる**＝リフトから速く DFCO 突入 |
| 減速カット率（エンリーン率）| `0xCC774` | float 6ギア×5RPM | 0.007〜0.05 | **上げる**＝全カットに速く到達 |
| 〃 In-Gear/ブレーキON | `0xCC694` | float | 0.007 | 上げる |
| 〃 In-Gear/ブレーキOFF | `0xCC698` | float | 0.015 | 上げる |
| 〃 Not In-Gear/MT | `0xCC6A0` | float | 0.007 | 上げる |

### 機構 RE（2026-11-13・読み取りのみ）

- **突入デバウンス**：コード `0x42620`–`0x4263E`。`*(0x4264C)`＝RAMカウンタ(0xFFFF7324)、`*(0x42670)`＝
  `0xC477D`（必要カウント）。`cmp/hs カウンタ, 必要カウント` → カウンタ≥必要カウントで減速フラグ
  (0xFFFF7336)=1、未満で0。つまり**カウントを下げると、より少ない周期で DFCO が立ち上がる**。
  `ncecu/sh2emu.py` でこの関数をエミュレートし、enter_count=30/8/3 でフラグが立つ閾値が 30/8/3 と
  一致することを実証（truth: counter 0/5/29→0, 30/31→1）。
- **カット乗数**：開始値 `0xCC6A4`=0.6875 から、上表のエンリーン率で毎周期減り、全カットしきい値
  `0xCC690`=0.6 を割ると全噴射停止。高回転列は純正で既に 0.05（速い）、低回転列は 0.007（穏やか＝
  アイドル付近の息つき防止）。レート大＝全カットに早く到達。
  → **突入後のカットは高回転では元々速い**ので、シフトアップの主律速は**突入デバウンス（30カウント）**。
  短いシフト操作の間に減速状態へ入り切らず燃料が流れ続けることがレブハングの一因。

## 4. 変更しない番地（失速防止・安全）

いずれも**純正のまま**。回転落ちを速めても失速側は純正の保護がそのまま効く、という安全設計。

- `0xC47FC` 減速維持の最低回転 **2312.5rpm**（＝突入にも必要／これ未満で燃料復帰）。失速防止の下限。
- `0xC4800` ヒステリシス 93.75rpm。
- `Decel Fuel Restore Idle Thresholds`（`0xC48xx`/`0xC49xx`：推定アイドル回転の加算・リミッタ・復帰判定）。
  実回転が推定アイドルへ落ちる前に燃料を戻してエンストを防ぐロジック。
- 復帰レート `0xCC6A8`/`0xCC6AC` ほか（カットから燃料を戻す速さ）。
- 全カットしきい値 `0xCC690`(0.6)・開始値 `0xCC6A4`(0.6875)（カットの“深さ/始点”は純正）。
- **閉ペダルでのスロットル目標**＝純正で既に 0（§5）。

参考：閉ペダル時のスロットル指令は純正で全RPM行 0.0。RE で確認（APP→TP Desired, APP=0/2.3% 列）:

```
1st control @0xC7EE4  row0..9: [APP0=0.0, APP2.3=0.0, APP5=2.0, 3.4, 5.0]
4-6 control @0xC8754  row0..5: [0.0, 0.0, 5.0, 7.5, 10.0]  (高回転行は 6.5 まで)
```

## 5. レバー2（減速スロットル/ダッシュポット）＝RE 済みだが本件では扱わない

- 閉ペダルでのスロットル**目標**は純正で既に 0%（§4）。よって残るレブハング寄与は「過渡の閉じレート
  （スロットルを 0 へ落とす速さ＝ダッシュポット）」。
- この閉じレートは **LibreTuner 定義に無い**（スロットル/トルクの rate/slew/decay/filter 系テーブルは
  定義上ゼロ件）。DBW 希望スロットル経路のコード定数（制御 ~`0x939xx` / 監視 ~`0x954xx`）。
- アイドル目標スルーレート（`0xD6AB8` ほか）が**監視プロセッサ保護**で実車 P0606＋リンプ却下された
  （§13）のと**同じ保護クラス**にあたる可能性が高い。閉じレートは DBW/トルク要求の監視対象で、
  片側だけ変えれば整合チェックで弾かれる恐れがある。
- したがって**本件では閉じレートには触れない**（高リスク・likely-protected）。将来追う場合の入口＝
  上記コード領域の RE と、制御↔監視の写し（電スロ 1:1 化と同じ同値更新が必要か）の確認。
- そもそもシフトアップ回転落ちの主因は**燃料（DFCO）**で、スロットルは既に全閉指令。燃料側だけで
  十分に効く見込み。

## 6. 編集方法（実装）

`ncecu/revdrop.py`：
- `build(base, *, enter_count=None, enlean_scale=1.0)` → `(rom, changes)`。
  - `enter_count`（1〜30、None=現在値維持）。`enlean_scale`（1.0〜8.0、1.0=純正）。
  - **既定（未指定）は inert＝純正とバイト等価**。保存時 `ncecu.checksum` で全領域自動補正。
  - `verify_base`：ROMサイズ＋コードのリテラルプール署名（`0x42670→0xC477D`, `0x93E08→0xCC774`）＋
    失速防止下限が純正範囲、を確認。未対応ROMは弾く。
  - `verify_result`：想定番地（`0xC477D` と `0xCC774`/`694`/`698`/`6A0`、チェックサム表）以外は
    一切変化しないことと、触らない番地（`0xC47FC`/`0xCC690`/`0xCC6A4`）が不変であることを保証。
  - エンリーン率は `min(0.30, 純正値×scale)` でクランプ。
- プリセット：`off`(=inert) / `mild`(enter 8, scale 2.0) / `strong`(enter 3, scale 3.0)。

CLI `tools/patch_revdrop.py`：
```
python tools/patch_revdrop.py --base rom_data/<現在のROM>.bin --out rom_data/revdrop_mild.bin --preset mild
python tools/patch_revdrop.py --base rom_data/<現在のROM>.bin --out rom_data/out.bin --enter-count 6 --enlean-scale 2.5
python tools/patch_revdrop.py --base rom_data/<現在のROM>.bin --out rom_data/inert.bin --preset off   # 入力と同一(検証用)
```

エディタ：設定→パッチ→「回転落ち高速化（レブハング低減）」。プリセット or 個別値を選び、適用後は
変更一覧（リザルト）を before→after で表示。保存するまでファイルは不変（保存時チェックサム自動補正）。

## 7. トレードオフ・注意

- **速くしすぎると**：シフトのつながりがガクつく／低回転コーストで息つき感。`enter_count` を下げるほど、
  また `enlean_scale` を上げるほど強い。まず `mild` から、ベンチで段階的に。
- 失速はしない設計（§4 の下限・復帰を純正のまま）だが、復帰しきい値（2312.5rpm）で燃料が戻るときに
  わずかなサージを感じうる。
- `ncecu/antilag.py`（オーバーランのポップ）とは**同じ番地を逆向きに使う**（ポップ＝カット率を下げる／
  本件＝上げる）。両立しないので、1つの ROM にはどちらか一方。
- DFCO は燃料側の機能なので、効果は**エンジン始動＋実コースト**で現れる（停車ベンチでは「回転落ち」の
  体感は出にくい）。検証はダッシュボード/ライブログで RPM・減速ステータス(0xFFFF6FCC)・L2旗
  (0xFFFF2124)・DTC を記録しながら行う。手順＝この文書の末尾「段階ベンチ手順」。

## 8. 元に戻す

- エディタ「回転落ち高速化」→「純正に戻す（inert）」、または CLI `--preset off` ＝純正とバイト等価。
- 戻すときは、適用前のROM（または `rom_data/` の吸い出し原本＝完全純正）を
  書き戻し＋電源入れ直し。

## 段階ベンチ手順（回転落ち高速化（DFCO強化）— 段階ベンチ手順）

`ncecu/revdrop.py`（シフトアップ時の回転落ちを速くする＝減速燃料カットを早く・強く）の
**停車→低速の段階的**な確認手順。解析・番地は `docs/revdrop_ja.md`。

> ⚠ 予備/ベンチECU専用。実車の純正PCMには書かない。フラッシュはユーザー明示確認のうえ別途。
> 燃料側のみ・スロットル不変＝E-Gas監視とは無関係だが、ドライバビリティ（息つき/ガクつき）の
> 確認が主眼なので段階的に。

### 0. 前提・持ち物

- 既知良好フルイメージを常備（適用前のROM、`rom_data/` の吸い出し原本＝完全純正）。
- 電源を転送中に落とさない。車上は終端を足さない（既に約60Ω）。
- 書込前後は `ncecu.checksum.all_valid` と `tools/ram_diff.py`/`romdiff` 系でダンプ照合。
- ログ：ダッシュボード/ライブログで **RPM・減速ステータス `0xFFFF6FCC`・クラッチ `0xFFFF7100`・
  L2旗 `0xFFFF2124`・DTC(Mode03/07)** を記録。AFR/点火時期(PID 0x0E)もあれば可。

### 1. inert（純正等価）で健全性確認

1. `python tools/patch_revdrop.py --base rom_data/<現在のROM>.bin --out rom_data/revdrop_inert.bin --preset off`
2. `revdrop_inert.bin` が入力のROMと**バイト一致**（差分0）であることを確認（＝ツールが余計な
   ことをしていない）。本来これは書く必要すら無いが、工程の空試験として。
3. （必要なら）書込→起動→**DTCなし・アイドル正常**を確認。段階Cのフラットシフト等が従来どおり動くこと。

### 2. 段階A：停車・空ぶかしで“燃料が切れるか”と DTC

目的：DFCO 強化が DTC やリンプを出さないこと、エンストしないことの一次確認。停車では「回転落ちの
速さ」の体感は出にくい（負荷が無い）が、**燃料カットの早さと復帰の健全性**は見える。

1. `--preset mild`（enter_count=8 / scale 2.0）を適用した ROM を書込。
2. 始動→暖機。**DTCなし**・アイドル安定・L2旗 `0xFFFF2124`=0 を確認（起動直後に P0606/P0601、
   スロットルのリンプ＝高アイドル固定が出たら**即中止**＝§5）。
3. 軽く空ぶかし（2000〜3500rpm）→アクセル全戻し。ライブで：
   - 減速ステータス `0xFFFF6FCC` が減速（カット）側に入るか、AFR が無噴射/リーンへ振れるか。
   - 回転がアイドルへ落ちる手前で**きちんと燃料復帰**し、**アイドルへ戻る/エンストしない**こと。
4. 問題なければ `--enter-count 4`〜`3`、`--enlean-scale 2.5`〜`3.0` と**段階的に強め**、毎回 2〜3 を再確認。

### 3. 段階B：低速・実走での回転落ちとツキ

目的：シフトアップ時の**回転落ちが速くなったか**と、ドライバビリティ（ガクつき/息つき）の確認。

1. 安全な場所で低速走行。2速→3速など**低めの回転でのシフトアップ**から。
2. アクセル戻し→クラッチ切りで、**回転が純正より速く落ちる**か（ログの RPM 立ち下がり勾配で比較。
   `mild` 適用前後の同条件ログを突き合わせる）。
3. 体感チェック：
   - シフトのつながりが**ガクつかない**か（速すぎるとクラッチ接時に段付き）。
   - 低回転コーストで**息つき/失速寸前**が出ないか（出るなら `enter_count` を戻す/`enlean_scale` を下げる）。
   - 踏み直し（ツキ）が**鈍くなっていない**か（DFCO 復帰は純正のままなので基本不変のはず）。
4. 問題なければ通常走行の回転域（3速→4速、4速→5速…）へ広げる。

### 4. 中止条件（どれかで即中止→戻す）

- DTC（P0606/P0607 プロセッサ系、P0601 ROM整合、P2110 等スロットル系、失火 P030x）。
- L2旗 `0xFFFF2124`≠0、またはスロットルがリンプ（`0xFFFF56C8` が高値固定＝高アイドル）。
- コーストでのエンスト/失速、または強いサージ/ガクつきで常用に耐えない。

### 5. 戻し方

- エディタ「回転落ち高速化」→「純正に戻す（inert）」で純正等価 ROM にして書込、または
  適用前のROM／`rom_data/` の吸い出し原本（完全純正）を書き戻し。
- 書込→**電源入れ直し**。学習値(KAM)は cal と無関係なので、書き戻しだけで再学習は強制されない
  （`mem:ecu-kam-learning`）。万一の書込失敗は電源再投入＋CAN再書込で復旧実績
  （`mem:flash-recovery-empirical`、先頭8KB保護）。

### 6. 推奨の進め方（まとめ）

inert で空試験 → `mild` で停車DTC確認 → `mild` で低速実走の回転落ち/ツキ → 必要なら段階的に
`enter_count`↓・`enlean_scale`↑ → 各段で L2旗0・DTCなし・エンストなしを確認。速くしすぎない。
